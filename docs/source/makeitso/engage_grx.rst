Engage for MAGE with WACCM-X (GRX)
=============================================


Introduction
------------

The Python script ``engage.py`` was developed to simplify the process of
configuring and running GRX MAGE (that is, the geospace application of the
``kaiju`` software with WACCM-X.) For a GRX run, ``engage.py`` asks for its
own parameters, then for those of ``makeitso.py`` and the ``waxrun`` script,
and prepares the necessary files for a GRX MAGE model run.

``engage.py`` prepares a GRX run when it is run with ``--component grx``. GRX
runs are supported on the ``derecho`` supercomputer only, with the software
built as described :doc:`here </building/buildDerecho_GRX>`. The command-line
options of ``engage.py`` are described :doc:`here </makeitso/engage>`, and a
complete walkthrough of a GRX run is available
:doc:`here </running/geoGRXQuickStart>`.


An example in ``BASIC`` mode
----------------------------

This section provides an annotated example session of ``engage.py`` running
in the default ``BASIC`` mode on the ``derecho`` supercomputer. Run:

.. code-block:: bash

  engage.py --component grx

This opens an arrow-key wizard that asks the questions of this session, one at a time: type a
value or press :kbd:`Enter` to accept the default and go to the next one.
The keys are listed at the bottom of the screen: ``↑ back   ↓/Enter next   Ctrl-S finish   Ctrl-R reset   Ctrl-C cancel``.
This is the recommended way to run ``engage.py``.
The wizard asks the following questions. They are shown here, for reference,
as the plain prompts that ``--no-tui`` prints (the fallback when your terminal
cannot show the wizard; the tool also falls back by itself):

1. ``engage`` native parameters will be requested
#####################################################

.. code-block:: bash

  Name to use for PBS job(s) [geospace]:

Enter an identifying string to use for your model run. This name will be used
as the basis for most of the files created by ``engage.py``, the ``kaiju``
software and WACCM-X. The default name is ``geospace``.

.. code-block:: bash

  Start date for simulation (yyyy-mm-ddThh:mm:ss) [2013-03-16T16:00:00]:
  Stop date for simulation (yyyy-mm-ddThh:mm:ss) [2013-03-18T12:00:00]:

Enter the start and stop date and time of the coupled run. The required solar
wind data will be fetched from CDAWeb, and converted into a format usable by
the ``kaiju`` software.

.. code-block:: bash

  GAMERA grid type (Q) [Q]:

A GRX run uses the quad- (``Q``) resolution LFM grid, so it is the only
choice offered.

.. code-block:: bash

  Name of HPC system (derecho) [derecho]:

GRX runs are supported on the ``derecho`` supercomputer only, so it is the
only choice offered.

.. code-block:: bash

  PBS account name (your projects: <YOUR_ACCOUNT_HERE>): <YOUR_ACCOUNT_HERE>

Enter the PBS account to charge for your jobs. On ``derecho`` the prompt
lists your projects and there is no default.

.. code-block:: bash

  Run directory [.]:

Specify the directory that you wish to perform the simulation in. The
directory will contain all of the files generated by ``engage.py``, including
the WACCM-X cases (in ``wax_case`` and ``cesm``), the submit script and the
three replay files ``engage_parameters.json``, ``makeitso_parameters.json``
and ``waxrun_parameters.json``.

.. code-block:: bash

  Path to kaiju installation [<YOUR_KAIJUHOME_HERE>]:
  Path to kaiju build directory [<YOUR_KAIJUHOME_HERE>/build_grx]:

Enter the paths to the location of your ``kaiju`` code, and the location of
your ``kaiju`` build directory. The defaults are ``$KAIJUHOME`` and
``$KAIJUHOME/build_grx``.

.. code-block:: bash

  PBS queue name (develop|main) [main]:

Select a PBS queue to use on the selected supercomputer.

.. code-block:: bash

  Job priority (premium|regular|economy) [economy]:

Select the job priority for your PBS jobs on ``derecho``.

.. code-block:: bash

  Requested wall time for each PBS job segment (HH:MM:SS) [12:00:00]:

Specify the wall clock time to request for each segment of your job. The
default is ``12:00:00``.

.. code-block:: bash

  Suggested segment for walltime 12:00:00 on main: 14400 s (4 h); valid values (seconds): [14400 (4 h)]
  Segment length in simulated seconds [14400]:

A GRX run is always split into multiple PBS jobs that are chained together,
with each using the results of the previous job as a starting point. Before
this prompt, ``engage.py`` prints the segment length it suggests for your wall
time and queue, and the valid values. With the default dates and 4-hour
segments, the coupled run is split into 11 segments.

.. code-block:: bash

  Extend TFIN by dtCouple - 1 seconds (T|F) [T]:

This option extends the end time (TFIN) of each coupled segment except the
last by ``dtCouple - 1`` seconds. It is set to ``T`` by default.


2. ``makeitso`` parameters will be requested
#####################################################

.. code-block:: bash

  Do you have an existing solar wind file to use? (Y|y|N|n) [N]:

If you already have a file containing solar wind data to use for the
boundary conditions of your simulation, enter ``Y``, and you will then be
prompted for the path to the file. If you don't have the file, enter ``N``
and the data for the dates you entered above will be fetched from CDAWeb.

.. code-block:: bash

  (GAMERA) Relative path to HDF5 file containing solar wind data [bcwind.h5]:

This is the name of the solar wind file in the run directory. When the data
are fetched from CDAWeb, ``makeitso.py`` writes them to this file.

.. code-block:: bash

  (VOLTRON) File output cadence in simulated seconds [60.0]:

How often (in simulated seconds) the ``kaiju`` software should output results
during the course of the simulation.

The script then runs several additional tools to prepare the files needed for
your simulation. This part ends with a line like this:

.. code-block:: bash

  makeitso: wrote 13 GRX voltron config files to <YOUR_RUN_DIRECTORY_HERE> (2 GR lead-in decks in gr_spinup/)


3. ``waxrun`` parameters will be requested
#####################################################

.. code-block:: bash

  Instructions:
  -> Default Selected input parameter is given in GREEN
  -> Warnings and Information are given in YELLOW
  -> Errors are given in RED
  -> Valid values (if any) are given in brackets eg. (value1 | value2 | value3)
  -> Enter '?' for any input parameter to get a detailed description
  -> 17 option(s) already set by engage are not asked again


  Run Options:

The ``waxrun`` options already set by ``engage``, such as the dates and the
account, are not asked again.

.. code-block:: bash

  CAM source tree (your clone) [<YOUR_CAM_TREE_HERE>]:

This is the path to your clone of the CAM source tree. The default is the
``WAXHOME`` environment variable, when you have set it.

.. code-block:: bash

  The default series covers 2003-12-11 to 2004-05-01 (winter and spring storms only).
  Start file directory: a CESM rest/ directory, a series root or one cam.i file (native ne30pg3 L145) [/glade/campaign/hao/itmodel/liuh/csm/waccmx_ne30_2004_cmip6/rest]:

This is the location of the WACCM-X restart files that the WACCM-X spin-up
can start from. The default series covers 2003-12-11 to 2004-05-01, as the
line above the prompt says.

.. code-block:: bash

  Generate nudging data? (yes/no) [Y]:

Enter ``yes`` (the default) to use the nudging data files that already exist
and to have a job written that generates any missing ones. If you enter
``no``, you will be prompted for a directory of existing nudging files.

.. code-block:: bash

  nearest restart: 2004-03-06T00:00:00, re-dated to 2013-03-06 (256 h of spinup)
  available: 2003-12-11T00:00:00, 2003-12-21T00:00:00, 2004-01-06T00:00:00, 2004-01-11T00:00:00, 2004-01-21T00:00:00, 2004-02-05T00:00:00, 2004-02-15T00:00:00, 2004-02-25T00:00:00, 2004-03-06T00:00:00, 2004-03-16T00:00:00, 2004-03-26T00:00:00, 2004-04-05T00:00:00, 2004-04-15T00:00:00, 2004-04-25T00:00:00, 2004-05-01T00:00:00
  Start file date (yyyy-mm-ddThh:mm:ss) [2004-03-06T00:00:00]:

Select the restart file that the WACCM-X spin-up starts from, by its date.
The script prints the restart nearest to the spin-up start it needs, and the
dates of the restarts that are available. The default is the nearest one.

.. code-block:: bash

  Spinup start date (yyyy-mm-ddThh:mm:ss) [2013-03-06T00:00:00]:

This is the date and time that the WACCM-X spin-up runs from; the start file
is re-dated to it. The default is derived from the start file date you
selected.

After these inputs, the script creates the two WACCM-X cases (the spin-up and
the coupled case) and builds WACCM-X, then writes the PBS files for the run
and the submit script ``geospace_grx.sh``. Building WACCM-X takes a long
time. With the default dates, the script also prints a ``WARNING`` that the
WACCM-X spin-up is 256 h rather than the requested 240 h; the spin-up length
is set by the start file you selected.

When finished, the script creates the files ``engage_parameters.json``,
``makeitso_parameters.json`` and ``waxrun_parameters.json`` in the run
directory. These files contain a record of all of the parameters used in your
simulation. They can be passed back to ``engage.py`` in a subsequent session
to repeat the simulation. In the run directory, add ``--clobber`` so that
the saved files can be overwritten, and ``--recreate-cases`` (see below):

.. code-block:: bash

  engage.py --component grx --clobber --recreate-cases -eo engage_parameters.json -mo makeitso_parameters.json -wo waxrun_parameters.json


Additional options for GRX
--------------------------

These options of ``engage.py`` are used only with ``--component grx``. The
full help text is shown :doc:`here </makeitso/engage>`.

The ``--dry-run`` option asks the same questions, but writes the WACCM-X case
settings as plain files in the ``dryrun`` subdirectory of the run directory,
instead of creating the cases.

The ``--skip-build`` option skips the build of both WACCM-X cases (spin-up
and coupled). Use it only when every ``cesm.exe`` already exists.

The ``--phase`` option selects which WACCM-X cases are generated: ``spinup``,
``coupled`` or ``both`` (the default).

The ``--recreate-cases`` option deletes and recreates both existing WACCM-X
cases in the run directory, together with any changes you made to them by
hand. The ``--clobber`` option never deletes a WACCM-X case.

More information on the files created by ``engage.py``, and on submitting the
run, is available :doc:`here </running/geoGRXQuickStart>`.
