Engage for MAGE with TIEGCM (GRT)
=============================================


Introduction
------------

The Python script ``engage.py`` was developed to simplify the process of
configuring and running GRT MAGE (that is, the geospace application
of the ``kaiju`` software with TIEGCM.) For a GRT run, ``engage.py`` asks for
its own parameters, then for those of ``makeitso.py`` and TIE-GCM's
``tiegcmrun`` script, and prepares the necessary files for a GRT MAGE model
run.

GRT is the default run type of ``engage.py`` (``--component grt``). The
command-line options of ``engage.py`` are described :doc:`here
</makeitso/engage>`, and a complete walkthrough of a GRT run is available
:doc:`here </running/geoGRTQuickStart>`.


An example in ``BASIC`` mode
----------------------------

This section provides an annotated example session of ``engage.py`` running
in the default ``BASIC`` mode on the ``derecho`` supercomputer. Run:

.. code-block:: bash

  engage.py

This opens an arrow-key wizard that asks the questions of this session, one at a time: type a
value or press :kbd:`Enter` to accept the default and go to the next one.
The keys are listed at the bottom of the screen: ``↑ back   ↓/Enter next   Ctrl-S finish   Ctrl-R reset   Ctrl-C cancel``.
This is the recommended way to run ``engage.py``.
The wizard asks the following questions. They are shown here, for reference,
as the plain prompts that ``--no-tui`` prints (the fallback when your terminal
cannot show the wizard; the tool also falls back by itself):

1. ``engage`` native parameters will be requested
#####################################################

.. code-block:: bash

  Name to use for PBS job(s) [geospace]:

Enter an identifying string to use for your model run. This name will be used
as the basis for most of the files created by ``engage.py``, the
``kaiju`` and ``TIE-GCM`` software. The default name is ``geospace``.


.. code-block:: bash

  Start date for simulation (yyyy-mm-ddThh:mm:ss) [2001-06-01T23:00:00]:
  Stop date for simulation (yyyy-mm-ddThh:mm:ss) [2001-06-02T01:00:00]:

Enter the start and stop date and time for the solar wind data you want to
use. The required data will be fetched from CDAWeb, and converted into a
format usable by the ``kaiju`` software. The run length must be a whole number
of hours.

.. code-block:: bash

  GAMERA grid type (D|Q|O) [Q]:

The codes represent double- (``D``), quad- (``Q``) and oct- (``O``)
resolutions in the LFM grid used in the ``kaiju`` software.

.. code-block:: bash

  Name of HPC system (derecho|aitken|linux|perlmutter) [derecho]:

The ``engage.py`` script supports the ``derecho`` and ``aitken``
supercomputers for a coupled GRT run; ``linux`` and ``perlmutter`` are
experimental. The default is the machine you run ``engage.py`` on. The
selection you make here will customize the remaining prompts for the selected
system.

.. code-block:: bash

  PBS account name (your projects: <YOUR_ACCOUNT_HERE>): <YOUR_ACCOUNT_HERE>

Enter the PBS account to charge for your jobs. On ``derecho`` the prompt lists
your projects and there is no default; on ``aitken`` the default is your login
name.

.. code-block:: bash

  Run directory [.]:

Specify the directory that you wish to perform the simulation in. The
directory will contain all of the files generated by ``engage.py``: the
``makeitso`` and TIE-GCM files, the coupled PBS scripts, the submit script and
the three replay files ``engage_parameters.json``,
``makeitso_parameters.json`` and ``tiegcmrun_parameters.json``. A relative
path is taken relative to the directory you run ``engage.py`` from, and the
directory is created if it does not exist. ``--clobber`` is needed when the
replay files already exist in that directory.

.. code-block:: bash

  Path to kaiju installation [<YOUR_KAIJUHOME_HERE>]:
  Path to kaiju build directory [<YOUR_KAIJUHOME_HERE>/build_grt]:

Enter the paths to the location of your ``kaiju`` code, and the location of
your ``kaiju`` build directory. The defaults are ``$KAIJUHOME`` and
``$KAIJUHOME/build_grt``.

.. code-block:: bash

  PBS queue name (develop|main) [main]:

Select a PBS queue to use on the selected supercomputer.

.. code-block:: bash

  Job priority (premium|regular|economy) [economy]:

Select the job priority for your PBS jobs on ``derecho``. This prompt is not
shown on ``aitken``.

.. code-block:: bash

  Requested wall time for each PBS job segment (HH:MM:SS) [12:00:00]:

Specify the wall clock time to request for each segment of your job. The
default is ``12:00:00``. A wall time that is too long for the queue, or too
short to hold a one-hour segment, is asked again.

.. code-block:: bash

  Do you want to split your job into multiple segments? (Y|y|N|n) [Y]:

Here ``Y`` is the default. This will split your simulation into multiple PBS
jobs that are chained together, with each using the results of the previous
job as a starting point. If you enter ``N``, the whole run must fit in one
wall time.

.. code-block:: bash

  Suggested segment for walltime 12:00:00 on main: 7200 s (2 h); valid values (seconds): [3600 (1 h), 7200 (2 h)]
  Segment length in simulated seconds [7200]: 3600

Enter the length of each segment in simulated seconds. The line above the
prompt shows the suggested length for your wall time, which is the default,
and the valid values; segments are whole hours. For example, if you enter
``3600``, the simulation will be split into two segments, each one hour long.
The first segment will run from ``2001-06-01T23:00:00`` to
``2001-06-02T00:00:00``, and the second segment will run from
``2001-06-02T00:00:00`` to ``2001-06-02T01:00:00``. If the segment length does
not divide the run, the last segment is shorter.

.. code-block:: bash

  Conda environment to use for the simulation [<YOUR_CONDA_ENVIRONMENT_HERE>]:

This is the name of the conda environment that you want to use for the
simulation. This is automatically set to the conda environment that you have
activated when you run the ``engage.py`` script.

.. code-block:: bash

  Extend TFIN by dtCouple - 1 seconds (T|F) [T]:

This option extends the end time (TFIN) of each coupled segment except the
last by ``dtCouple - 1`` seconds. It is set to ``T`` by default.


2. ``makeitso`` parameters will be requested
#####################################################

.. code-block:: bash

  Do you have an existing solar wind file to use? (Y|y|N|n) [N]:

If you already have a file containing solar wind data to use for the boundary
conditions of your simulation, enter ``Y``, and you will then be prompted for
the path to the file. If you don't have the file, enter ``N`` and the data for
the dates you entered above will be fetched from CDAWeb.

.. code-block:: bash

  (GAMERA) Relative path to HDF5 file containing solar wind data [bcwind.h5]:

This is the name of the solar wind file in the run directory. When the data
are fetched from CDAWeb, ``makeitso.py`` writes them to this file.

.. code-block:: bash

  (VOLTRON) File output cadence in simulated seconds [60.0]:

How often (in simulated seconds) the ``kaiju`` software should output results
during the course of the simulation.

The script then runs several additional tools to prepare the files needed for
your simulation. An example of this output is shown :doc:`here
</running/geoGRTQuickStart>`.

3. ``tiegcmrun`` parameters will be requested
#####################################################

.. code-block:: bash

  Instructions:
  -> Default Selected input parameter is given in GREEN
  -> Warnings and Information are given in YELLOW
  -> Errors are given in RED
  -> Valid values (if any) are given in brackets eg. (value1 | value2 | value3)
  -> Enter '?' for any input parameter to get a detailed description


  Run Options:
  User Mode = BASIC
  Compile = False
  Execute = False
  Coupling = True
  Engage = True

.. code-block:: bash

  Directory of model [<YOUR_TIEGCMHOME_HERE>]:
  Directory of Tiegcm Data Files [/glade/campaign/hao/itmodel/tiegcm3.0/new_data]:

This is the path to your TIE-GCM repository and TIE-GCM data directory. These
are automatically set to the ``TIEGCMHOME`` and ``TIEGCMDATA`` environment
variables.

.. code-block:: bash

  Standalone Executable [<YOUR_RUN_DIRECTORY_HERE>/tiegcm.exe]:

This is the path to the TIE-GCM standalone executable. The default is
``tiegcm.exe`` in the run directory, so either copy the executable there or
type its path.

.. code-block:: bash

  Coupled Executable [<YOUR_RUN_DIRECTORY_HERE>/tiegcm.x]:

This is the path to the TIE-GCM coupled executable. The default is
``tiegcm.x`` in the run directory; an executable outside the run directory is
run from where it is, so no copy is needed. ``engage.py`` warns when an
executable does not exist yet, and refuses one built for another grid (for a
``Q`` grid run, ``tiegcm.exe`` at 2.5 degrees and ``tiegcm.x`` at 1.25
degrees).

.. code-block:: bash

  Low = 70, Medium = 140 , High = 200
  F107 flux level for TIEGCM spin up (low|medium|high) [low]:

This is the F10.7 flux level to use for the TIE-GCM source file in spin-up
period. The default is ``low``, which corresponds to a value of 70. The other
options are ``medium`` (140) and ``high`` (200).

.. code-block:: bash

  SOURCE file location [/glade/campaign/hao/itmodel/tiegcm3.0/new_data/source/junsol_f70.nc]:

This is the path to the TIE-GCM source file to use for the spin-up period. The
default is automatically selected based on the start date of your simulation
and the flux level.

.. code-block:: bash

  STEP number [30]:
  NSTEP_SUB number [10]:

These parameters are set as default by ``tiegcmrun``.

.. code-block:: bash

  Secondary Output Fields [['TN', 'UN', 'VN', 'O2', 'O1', 'HE', 'N2', 'N2D', 'N4S', 'NO', 'NE', 'Z', 'WN', 'DEN', 'TEC']] / ENTER to go next:

These are the secondary output fields to include in the TIE-GCM output.
The default is a set of fields that are commonly used in geospace simulations.
You can add another field if you wish, or just hit :kbd:`Return` to accept the
default.

.. code-block:: bash

  High-latitude potential model that is going to be used (HEELIS|WEIMER) [HEELIS]:

This is the high-latitude potential model to use in the TIE-GCM simulation.
The default is ``HEELIS``, the Heelis potential model.

.. code-block:: bash
  :force:

  If GPI_NCFILE is specified, then KP and POWER/CTPOTEN are skipped. If further POTENTIAL_MODEL is WEIMER and IMF_NCFILE is specified, then the Weimer model and aurora will be driven by the IMF data, and only F107 and F107A will be read from the GPI data file.
  Enter 'gen' to generate a GPI file for this run's dates with gcmprocpy (27-day trailing F10.7 average).
  GPI file [/glade/campaign/hao/itmodel/tiegcm3.0/new_data/boundary_files/GPI/gpi_1960001-2026180.nc]:

This is the path to the GPI file to use for the TIE-GCM simulation, which
contains the F10.7 and Kp indices. The default is the newest GPI file in the
TIE-GCM data directory when it covers your run, and ``gen`` otherwise.

After these inputs, the script interpolates the source file for TIE-GCM, and
generates the namelist, XML and PBS files for the run.

When finished, the script creates the files ``engage_parameters.json``,
``makeitso_parameters.json`` and ``tiegcmrun_parameters.json`` in the run
directory. These files contain a record of all of the parameters used in your
simulation. They can be passed back to ``engage.py`` in a subsequent session to
repeat the simulation. In the run directory, use this command:

.. code-block:: bash

  engage.py --clobber -eo engage_parameters.json -mo makeitso_parameters.json -to tiegcmrun_parameters.json

More information on the files created by ``engage.py``, and on submitting the
run, is available :doc:`here </running/geoGRTQuickStart>`.
